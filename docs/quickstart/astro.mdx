# Astro

```bash
bun create @heyo-sh/heyo-cms my-cms --template astro --deployment vercel --database postgres
cd my-cms
cp .env.example .env     # set DATABASE_URL
bun run db:migrate
bun run seed
bun run dev
```

- the site — `http://localhost:4321`
- the panel — `http://localhost:4321/api/heyo-cms/admin`
- the API — `http://localhost:4321/api/heyo-cms/posts`

The panel asks you to create the administrator on first open, and closes that
form behind the account it creates. `bunx heyo-cms create-admin --email
you@example.com` does the same from a shell.

## The mount

```ts
// src/pages/api/heyo-cms/[...path].ts
import { cmsHandler } from "@heyo-sh/heyo-cms/astro";

import { cms } from "../../../../heyo-cms.config.ts";

export const prerender = false;
export const { GET, POST, PATCH, PUT, DELETE, HEAD, OPTIONS } = cmsHandler(cms);
```

Astro hands an endpoint context rather than a `Request`, which is the only
difference from the Next.js adapter and the reason the import path names the
framework.

## Reading content in a page

```astro
---
import { cms } from "../../heyo-cms.config.ts";

export const prerender = false;
const { docs } = await cms.api.posts.find({ limit: 10 });
---

<ul>{docs.map((post) => <li>{post.title}</li>)}</ul>
```

## One setting the template changes for you

`astro.config.ts` sets `security.checkOrigin: false`. Astro refuses any
form-encoded POST whose `origin` does not match, which also refuses every API
client that is not a browser — `curl -F file=@photo.jpg` sends no origin, so
uploads from these clients would be rejected. The CMS uses `SameSite=Lax`
session cookies and bearer tokens for non-browser clients. SameSite protects
cross-site POSTs, not same-site sibling origins: deploy on a trusted site,
keep mutations off GET routes, and add explicit origin checks where needed.
Re-enable Astro's check for additional cookie-authenticated form endpoints.
