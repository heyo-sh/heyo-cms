# React Router

```bash
bun create @heyo-sh/heyo-cms my-cms --template react-router --deployment vercel --database postgres
cd my-cms
cp .env.example .env     # set DATABASE_URL
bun run db:migrate
bun run seed
bun run dev
```

- the site — `http://localhost:5173`
- the panel — `http://localhost:5173/api/heyo-cms/admin`
- the API — `http://localhost:5173/api/heyo-cms/posts`

The panel asks you to create the administrator on first open, and closes that
form behind the account it creates. `bunx heyo-cms create-admin --email
you@example.com` does the same from a shell.

## The mount

```ts
// app/routes/api.heyo-cms.$.ts
import { cmsHandler } from "@heyo-sh/heyo-cms/react-router";

import { cms } from "../../heyo-cms.config.ts";

export async function loader({ request }: { request: Request }) {
  return cmsHandler(cms).loader({ request });
}
export const action = loader;
```

Two exports rather than seven: React Router reads through `loader` and writes
through `action`, and the method dispatch happens inside the handler where it
already lives. The route is registered as a splat in `app/routes.ts`.
Keep CMS calls inside server exports so React Router can remove them from the
browser bundle; do not evaluate `cmsHandler(cms)` at module scope.

## Reading content in a route

```tsx
// app/routes/home.tsx
import { cms } from "../../heyo-cms.config.ts";

export async function loader() {
  const { docs } = await cms.api.posts.find({ limit: 10 });
  return { posts: docs };
}

export default function Home({ loaderData }) {
  return (
    <ul>
      {loaderData.posts.map((p) => (
        <li key={p.id}>{p.title}</li>
      ))}
    </ul>
  );
}
```

## On Cloudflare

The Cloudflare template owns its Worker entry (`workers/app.ts`), so the
sweeps run from the platform's cron trigger rather than from an HTTP route,
and `react-router.config.ts` enables `future.v8_viteEnvironmentApi` — without
it React Router pre-bundles its server dependencies for Node and the Worker
fails at the first request with `module is not defined`.
