# Fields

```ts
import {
  boolean,
  date,
  json,
  list,
  media,
  multiselect,
  number,
  relation,
  richText,
  select,
  text,
  textarea,
  seoFields,
} from "@heyo-sh/heyo-cms/fields";
```

Every field accepts the common options (for `aiGenerate`, only textual built-ins
currently support generation):

```ts
text({
  required: true,
  localized: true, // stored as { [locale]: value }, read one at a time
  unique: true, // not available together with `localized`
  index: true,
  default: "Untitled",
  label: "Title",
  access: {
    // field-level, checked before any hook runs
    read: ({ actor }) => permits(actor, "posts:read_secret"),
    update: ({ actor }) => permits(actor, "posts:publish"),
  },
  admin: { placeholder: "Title", hidden: false },
  aiGenerate: { prompt: "Suggest a title for this document." },
});
```

## The types

| Type          | Stores               | Notable options                            |
| ------------- | -------------------- | ------------------------------------------ |
| `text`        | string               | `minLength`, `maxLength`, `pattern`        |
| `textarea`    | string               | the same, rendered as a box                |
| `richText`    | ProseMirror document | `nodes` — which nodes the panel offers     |
| `number`      | number               | `integer`, `min`, `max`                    |
| `boolean`     | boolean              | `default`                                  |
| `date`        | ISO string           | `mode: "date" \| "datetime"`               |
| `select`      | one of `options`     | `options`, `default`                       |
| `multiselect` | an array of options  | `minItems`, `maxItems`                     |
| `media`       | a `media` row id     | `accept` — a hint for the picker           |
| `relation`    | an id, or ids        | `relation("authors", { many: true })`      |
| `slug`        | a URL slug           | `from`, `history`, `maxLength`             |
| `json`        | anything JSON        | use `defineField()` for custom validation  |
| `list`        | an array of rows     | `fields` — one row; `minItems`, `maxItems` |
| `seoFields()` | four fields at once  | spread into `fields`                       |

`index: true` creates a non-unique, collection-scoped database index on the
field's value in the `documents` JSON body. It can speed up filtered lookups
but adds storage and write cost; it is **not** full-text search. `unique: true`
creates a unique index (no need to also set `index: true`). Localized values
cannot be unique and are not indexed by the current implementation.

`admin.placeholder` is used by text, textarea, rich-text and select controls;
media and other controls ignore it. `admin.hidden` removes the field from the
shipped form (not from the API). A field with `admin.hidden: true` **cannot**
have `required: true` — the configuration fails immediately, even if it has a
default. The removed `width`, `position` and `condition` options are rejected.
None of these options is access control.

## Slugs

`slug()` is a URL handle the engine looks after, on every write path — the
panel, the REST API, an import, a scheduled change, a script:

```ts
import { slug, text } from "@heyo-sh/heyo-cms/fields";

fields: {
  title: text({ required: true, localized: true }),
  slug: slug({ from: "title", localized: true, history: true }),
}
```

- **Made once.** While a document has no slug in a language, the first write
  with a `title` makes one: `"Łódź in Autumn"` becomes `lodz-in-autumn`, and
  `lodz-in-autumn-2` when that is taken. Retitling never moves it; clearing
  it (`slug: null`) makes it again. The panel shows a button that runs the
  same function on the draft.
- **Cleaned when typed.** `"  Kraków & Łódź!! "` is stored as `krakow-lodz`.
  Latin accents, Cyrillic and Greek are transliterated to ASCII, so a link
  never turns into `%D0%B1…` in a chat. A house style of your own — `&` as
  `and`, a language's own rules — is `slug({ slugify: (text) => … })`, used
  everywhere a slug is made or cleaned.
- **Unique per language.** A localized field cannot carry a database index
  (one index cannot cover languages that do not exist yet), so the engine
  checks it instead — against every document of the collection, trashed ones
  included, so restoring a page never collides. A typed slug that is taken is
  a `409`. A field that is not localized also gets a unique index.
  `unique: false` turns all of this off.
- **Remembered, with `history: true`.** A slug a document stops using becomes
  one of its _previous slugs_, kept in the `slug_history` table (which
  `heyo-cms generate` adds). Nobody else may take it, and it goes when the
  document is purged.

Finding a document by a slug from a URL — now or before:

```ts
const hit = await cms.api.posts.resolveSlug(params.slug, { locale: "pl" });
if (!hit) return notFound();
if (!hit.current || hit.locale !== "pl") {
  // An old address, or a slug from another language: redirect to the
  // document's slug now, in the language of the page.
  return redirect(`/pl/blog/${hit.document.slug}`, 301);
}
```

The best match wins: a current slug in the requested language, then in
another language, then a previous slug — in the requested language first.
The document is read with the caller's access, in the requested locale, so a
draft a visitor may not read resolves to nothing.

Merging two pages is deleting the old page for good, then adding its slug to
the one that stays — while the old page exists, even in the trash, its slug is
still its own:

```ts
await cms.api.posts.purge({ id: old.id });
await cms.api.posts.addPreviousSlug({ id: kept.id, slug: "old-post", locale: "en" }); // prettier-ignore
await cms.api.posts.previousSlugs({ id: kept.id }); // newest first
await cms.api.posts.removePreviousSlug({ id: kept.id, slug: "old-post", locale: "en" }); // prettier-ignore
```

Over HTTP: `GET /<collection>/resolve-slug?slug=…&locale=…`, and
`GET`/`POST`/`DELETE /<collection>/<id>/previous-slugs`. The panel lists a
document's previous slugs under the field and lets an editor add and remove
them. `slugify()`, `isSlug()` and `slugPattern` are exported from
`@heyo-sh/heyo-cms/fields` for code that builds URLs itself.

A plain `text` field with a pattern is still the right choice for a handle
that is not a URL, or one you would rather fill in a hook of your own:

```ts
handle: text({
  unique: true,
  pattern: "^[a-z0-9]+(?:-[a-z0-9]+)*$",
  generate: ({ fields }) => slugify(String(fields.title ?? "")),
});
```

`generate` is a **server-side function**, called by a button beside the field
using the current draft. `fields` contains readable sibling values in the
current locale. Its result is validated against the target field schema,
inserted into the form, and is **not saved** until the editor saves. An
`aiGenerate` button can sit beside it; it uses AI and shows a preview first.

## Lists

`list()` is an ordered list of rows that share a few fields: the questions of
an FAQ, the sources of an article, a change log. The structure is the field's,
so nobody has to remember a format and nothing has to parse one:

```ts
faq: list({
  localized: true,
  maxItems: 12,
  fields: {
    question: text({ required: true, maxLength: 160 }),
    answer: textarea({ required: true, description: "Markdown." }),
  },
}),
references: list({
  fields: {
    title: text({ required: true }),
    url: url({ required: true }),
    publisher: text(),
  },
}),
```

The value is an array of objects — `[{ question: "…", answer: "…" }]` — stored
as JSON in the document, typed from the row's fields, and validated row by
row with their own schemas. A required field must be in every row; an
optional one may be `null` or left out; a key the row does not declare is an
error rather than a value silently dropped. A refused write names the row and
the field: `faq #2 question: is required`.

The list is the field: `localized`, `required`, `access`, `label` and
`description` go on the list, and a translation is a whole list of its own. A
row holds `text`, `textarea`, `email`, `url`, `number`, `boolean`, `date`,
`select` and `multiselect` fields; a relation, a media file, rich text or a
slug needs a loader, an editor or a uniqueness check that does not reach
inside a row, and is refused when the configuration loads, as are `localized`,
`unique`, `index` and `access` on a row's field.

In the panel each row is a small form, with buttons to move it and remove it
and one to add a row; the list view shows how many rows a document has. The
OpenAPI document describes the row, and the AI assistant is told its fields.

## Your own field

`defineField()` is public and the built-in types use nothing else:

```ts
import { defineField } from "@heyo-sh/heyo-cms";
import { z } from "zod";

export const stars = defineField<number, { max?: number }>({
  name: "stars",
  optionsSchema: z.object({ max: z.number().optional() }).passthrough(),
  schema: (options) =>
    z
      .number()
      .int()
      .min(0)
      .max(options.max ?? 5),
  column: () => ({ type: "integer" }),
});
```

`schema` validates, `column` tells the schema layer what to migrate, and the
zod schema is what `GET /openapi.json` documents — so validation and
documentation cannot disagree. The panel renders an unknown field with the
control implied by its column type until a plugin ships one through
`admin.scripts`.
